# 上下文守护 · 会话记忆继承（通用型）

> 长对话会悄悄吃掉 192K 上下文窗口（WorkBuddy 专属，已确认）。本 Skill 让 AI 在长任务里**主动防溢出、利用系统压缩、做快照、并能在会话之间搬运记忆**——不止"看护"，更是"上下文的搬运工"。

## 已确认事实（实测基线，非推测）

1. **WorkBuddy 存在系统级自动上下文压缩**，无需用户或 Skill 手动触发；压缩后占用显著回落。
2. **触发点不固定**：实测在 50%+ 到 80% 占用都见过系统压缩，且更像在**对话结束 / 空闲一阵后**才触发，并非严格按占用率卡点。
3. **Agent 读不到精确占用数字**：面板是 UI 展示层，无工具/变量可轮询，无法反推 token 数——只能请用户看面板确认。
4. **192K 为窗口上限（用户确认）**，但系统压缩不是无限兜底：长期超长对话经历多次压缩仍可能溢出（曾见占用冲到 99.6% 后失效）。因此不能因"有自动压缩"就放任——本 Skill 的价值是压缩前主动快照 + 外置记忆，把关键上下文搬出窗口。

## 何时加载（触发）

**原触发（监控类）**
- 任务明显较长（预计 >10 步 / 多轮工具调用 / 大文件读写 / 多次迭代）
- 用户提到：上下文 / 上下文窗口 / 上下文压缩 / 长对话 / 占用 70% 80% 90% / 对话变笨 / 记不住前面

**记忆继承类（通用化核心）——标准触发词：继承会话记忆**
- 用户口语化表述（均视为"继承会话记忆"触发）："上下文窗口有点满了" / "咱们开新的对话窗口" / "总结一下咱们之前的上下文" / "生成一个新窗口交接文档" / "接着上次的会话" / "继续之前那个任务" / "之前我们聊到哪了"
- 用户**开新任务并引用某记忆文件**（如"按 MEMORY.md 继续"）
- 用户要求**总结一下当前对话/上下文**以便后续复用
- 用户要**测窗口上限/观察压缩行为**（见下方实验章节）

## 硬约束（必须先说明）
- Agent **不向用户暴露"我检测到你到 X%"**——读不到精确数字，只能请用户看面板确认。
- **压缩是系统的，不是 Skill 的**——不要假装本 Skill 在压缩，也不要说"我做不了压缩所以完了"；系统会自动管。
- 本 Skill 的价值在于**压缩发生前/发生时主动保护关键上下文**（快照 + 外置记忆 + 摘要），让系统压缩不丢东西。

## 与系统内置记忆机制：一条线（不另起炉灶）

WorkBuddy **本身已有记忆机制**（系统层）：每日工作日志 `<workspace>/.workbuddy/memory/YYYY-MM-DD.md`、项目长期记忆 `<workspace>/.workbuddy/memory/MEMORY.md`、用户级 `~/.workbuddy/MEMORY.md`。本 Skill **不是第二套记忆，而是这套机制之上的「主动保护层 + 跨会话接棒器」**：

- **底座**：系统记忆机制负责持久化与跨会话读取。
- **本 Skill 的角色**：在压缩发生前主动把关键上下文**快照/沉淀进同一套系统记忆**（复用上述路径，不新建目录、不双写冲突），并在用户要"继承上下文"时读取同一套记忆来接棒。
- **一条线原则**：记忆只有 single source of truth = 系统记忆文件。本 Skill 的所有产出（快照、摘要、决策）都**直接落进系统记忆约定路径**，保持可 grep、可继承、不发散。

> 一句话：系统是仓库，本 Skill 是勤快的图书管理员——只往仓库里规整，不自己另开一个仓库。

## 五大融合能力

### 1. 上下文窗口监控
- 长任务开头声明"上下文管理"：预计体量、何时提醒看面板、临界如何接棒
- 自监测信号（命中即提醒用户看面板）：连续工具调用 ≥ 15 且未结束 / 单次大段输出 / 对话 ≥ 20 轮未收尾
- 阈值映射（用户主动管理参考线，非系统压缩触发点）：70% 收敛 / 80% 准备交接 / 90% 立即开新任务。注意——系统自动压缩**没有固定阈值**：实测在 50%+ 到 80% 都触发过，且更像在**对话结束 / 空闲一阵后**才压，而非纯按占用率卡点。

### 2. 压缩检测与自动快照（借鉴 Memory Manager）
- 在对话临界（或用户要求"总结/接棒"）时，自动生成**结构化上下文快照**：
  ```
  ## 上下文快照 · {日期/任务名}
  - 任务目标：
  - 已定关键决策：
  - 当前进度：
  - 涉及关键文件/路径：
  - 未决项 / 风险：
  - 下一步：
  ```
- 快照落盘到项目记忆（即 `<workspace>/.workbuddy/memory/MEMORY.md` 或当日日志 `YYYY-MM-DD.md`，与工作区记忆约定一致），可被新会话 grep/引用
- "压缩检测"在本 Skill 体现：主动察觉对话变长 → 不等系统压就先快照，避免压缩吞掉关键细节

### 3. 持久记忆外置（借鉴 Agent Memory / Elite Longterm Memory）
- 把**稳定事实、已确认决策、项目约定**写入长期记忆（项目 `MEMORY.md` 或用户级 `~/.workbuddy/MEMORY.md`），而非反复塞回对话窗口
- 从根上减少窗口压力——即使系统压缩，外置内容也不丢

### 4. 会话日志回顾（借鉴 Session-logs）
- 新任务开场若用户要"继承记忆"，先**读取项目记忆 / 当日日志**复盘关键结论，再接续
- 可跨会话引用旧结论、避免重复探索

### 5. 摘要能力（集成 Summarize / Summarize Pro）
- **何时总结**：每段实质性阶段收尾 / 临界 / 用户说"总结一下" / 需要继承复用 / 准备测窗口上限前
- **总结对象**：长上下文、整段对话、某模块工作
- **输出规范**：结构化 markdown（目标→决策→进度→文件→未决→下一步），可直接被新任务引用
- **原则**：基于真实材料回原文，不臆造；判断标注来源；推断前缀"推断："

## 阈值映射（用户看面板后对照执行）

> 先说清楚：系统自动压缩**无固定阈值**——实测在占用 50%+ 到 80% 都触发过，且多在**对话结束 / 空闲一阵后**才压，并非实时按占用率卡点。下表只是**你主动管理**的节奏参考，不是压缩开关。

| 面板占用 | 动作 |
|----------|------|
| **70%** | 收敛模式：停发散追问；新结论即时落盘记忆；不再重复背景；开始准备摘要 |
| **80%** | 准备交接：生成结构化上下文快照 + 沉淀已定决策到长期记忆 |
| **90%** | 立即开新任务：引用快照/记忆接棒；本任务只收尾，不再展开新子任务；交付"继承摘要" |

> 提示：本表是"用户主动管理"的参考线，**不是系统压缩触发点**。系统压缩无固定阈值、且常发生于对话空闲后，不要凭本表预判系统何时压。

## 会话记忆继承流程（记忆继承类触发时执行）
1. **读取**：读项目记忆 / 当日日志 / 用户指定的记忆文件，复盘关键结论
2. **对齐**：用 1–2 句复述已确认上下文，让用户校正偏差
3. **接续**：基于继承的上下文继续任务，不重复探索已定事项
4. **沉淀**：新进展即时写回记忆，保持记忆是最新 single source of truth

## 🧪 压缩行为实证实验（测窗口上限 / 观察系统压缩）

> 用户提出"测一个窗口的最高上限、看压缩有什么问题"。设计为**人机协作实验**：用户当传感器（看面板报数），Agent 当记录员 + 负载发生器。

### 实验目标
1. **压缩触发点**：占用升到多少时系统自动压缩（是固定阈值还是动态？）
2. **压缩后回落基线**：压完落到多少（如 28.4% 是否稳定基线？）
3. **窗口硬上限**：压缩前峰值能到多少？是否真有 192K 上限，还是能短暂超？
4. **压缩保真度**：压缩后早期关键设定/结论是否保留？（通过追问早期细节验证）

### 协作协议
- **用户（传感器）**：每隔几轮（或 Agent 请求时）看面板，报当前占用 % 与是否观察到"占用骤降"（=压缩发生）
- **Agent（记录员）**：维护下方数据表，周期性制造负载（大段输出 / 工具调用）逼出压缩
- **记录表**（追加到当日日志或本实验专用文件）：
  ```
  | 轮次 | 累计工具调用 | 本回合动作 | 用户报占用% | 观测到压缩? | 备注 |
  ```
- **保真度验证**：在压缩发生后，Agent 主动追问 1–2 个"早期对话里的具体设定"，看回答是否准确（验证压缩是否丢了细节）

### 实验产物
- 一份「WorkBuddy 上下文压缩行为报告」：触发点区间、回落基线、上限、保真度结论 + 原始数据表
- 结论回写本 Skill，更新"实测真相"章节，形成可复用的经验资产

### 注意事项
- 实验期间占用可能多次压缩/回升，属正常现象，记录波动即可
- 若用户报占用持续 < 30% 且长时间无压缩，说明当前负载不足以逼出压缩，需加大单轮输出/工具量
- 实验结束标志：拿到至少一次完整"升→压缩→落"周期 + 一次保真度验证
