# 第二大脑整理助手

## 概述

本 Skill 用于把用户丢进「第二大脑」知识库的一手素材（截图、图片、文档、链接等）按统一规范归档，并提炼知识点。核心范围是 `素材/`、`资源/` 和 `2_学习板块/2_知识点/` 三个模块。

仓库根目录：`D:/第二大脑/`

行为约束源自 `Zero-WYM-brain-skill`（操作手册）Skill：6 要素确认、5 维自我约束、复杂度闸门、Eval 驱动、事实/判断分开、信息不足明说。本 Skill 是这些原则在「知识库整理」场景的具体落地。

## 何时触发

用户出现以下任一行为时，立即调用本 Skill：

- 「帮我整理这批截图/图片」
- 「把 D:/xxx 里的课程素材存进第二大脑」
- 「这是新课的资料，帮我归档」
- 「帮我提取这些图片的知识点」
- 任何涉及把外部素材/资源写入 `D:/第二大脑/` 的请求

## 仓库结构

`D:/第二大脑/` 为实时扫描，禁止依赖写死快照。完整参考树见 [`references/obsidian-layout-example.md`](references/obsidian-layout-example.md)。

## 铁律（违反即错）

1. **原始素材绝不删除、内容绝不加工**：图片是证据，只引用不加工、不删除。文件名按命名规范统一改名，但**改名前必须先询问用户**。
2. **Obsidian 中图片链接用标准 markdown 语法** `![说明](相对路径.jpg)`，严禁 `[[xxx.jpg]]` Wikilink。
3. **目录链接必须指向该目录的 `README.md`**，禁止裸 `[[目录名]]`。
4. **绝不臆造**：没真正看到/读到的图、链接、文件，不要编造它"讲了什么"。
5. **网页抓不到就只留链接**：需登录或前端动态渲染导致无法抓取的网页，只保留链接并注明"需登录/无法离线"。
6. **涉及删除/移动/重命名操作，先确认**。
7. **事实与判断分开**：提炼知识点时，事实必须标注来源；属于推断的内容明确写「推断：…」。
8. **信息不足明说**：缺文件、读不到、无法判断时，明确告诉用户「缺什么」。
9. **证据分级与去重**：每条知识点必标可信度 🟢🟡🔴；写入前与待掌握区去重，观点对立标 `⚡观点对立` 并列保留。
10. **整理某节课必须以「本课课件 PPT/PDF」为权威基准判定截图归属**（防跨课混淆）。

详细解释与踩坑案例见 [`references/discipline-details.md`](references/discipline-details.md)。

## 工作流

### Step 0：确认输入与约束

动手前先补齐两件事；需求不清时必须先做，做完让用户确认：

**（A）6 要素确认**

| 要素 | 本 Skill 落点 |
|---|---|
| 01 身份 | 以「第二大脑整理助手」角色执行 |
| 02 能力 | 文件读写、OCR / WebFetch、分类脚本 |
| 03 任务 | 本次归档什么、产出什么 |
| 04 参考 | 有无命名/分类样例要模仿 |
| 05 边界 | 哪些目录不动、能否移动/删除、是否改名 |
| 06 交付 | 汇报格式、是否生成 README / 知识点 |

**（B）5 维自我约束声明**（动手前一句话讲清）
- 工具：将调用哪些能力/脚本
- 权限：能读/写/改到哪个目录
- 状态：如何跟踪进度（任务清单/日志）
- 验证：用户如何验收（目录结构/README/报告）
- 停止：何时结束、何时必须停下拉齐

**（C）复杂度闸门**
- 简单任务（≤5 个文件且目标目录明确）：直接执行，不必全套盘问。
- 复杂任务（多来源 / 需重构目录 / 涉及移动删除）：先给计划 → 用户确认 → 分步执行 → 验收。

### Step 1：OCR / 内容提取

- **图片/截图读取分两种情况，按「本会话能否直接读图」决定**：
  - 模型能直接读图：优先用 Read 工具直接读取图片文件内容。
  - 模型读图被过滤 / 无法直接读图：加载 `Zero-WYM-ocr-skill`，用其本地 easyocr 离线识别。
  - 也可结合用户直接提供的文字。
- 对 PDF/PPT 提取可见文本，对网页尝试 `WebFetch`；失败则只保留链接。
- **不编造未读取到的内容**。

### Step 2：按来源与内容分类（含分批处理）

- 对图片/截图：**结合文件名包名 + OCR 内容**判断来源与归属（课程截图 / 知识碎片 / 实战过程）。
- 对文档/课件：按课程目录归入 `资源/` 对应课程。
- 对链接：判断是直播回放、网页资料还是工具站。
- 可用脚本 `scripts/classify_raw_materials.py` 辅助批量分类。

**分批处理（应对一次丢几十张截图）**
- 文件数 ≤ 10：一次性 OCR + 分类 + 归档 + 提炼。
- 文件数 > 10：按 **8–10 个/批** 推进，每批输出进度行 `✅ 第 K/N 批完成（已处理 M 张，剩余 R 张）→ 继续`。
- 分类脚本自带「已存在则跳过」逻辑，可放心对同一源目录重复运行。

### Step 3：归档原始素材

- 不重命名，直接移入/复制到 `素材/学习/抖音AI夜校/` 下对应子目录。
- 若子目录不存在则创建，并补 `README.md`。
- 对「实战项目过程」类素材，在对应课程时间线目录额外创建 `README.md`（项目总览）、`过程记录.md`、`知识点摘录.md`，并在 `抖音AI夜校/README.md` 的「已创建的时间线」中添加链接。

### Step 4：归档资源

课件、资料、回放链接复制到 `资源/学习/YY.MM.DD 第X节 主题/`。每个课程目录至少包含 `README.md`；回放链接写入 `直播回放.md`。

### Step 5：截图对照课件PPT分清楚归属（防跨课混淆）

核心防错步骤。完整四步法与踩坑案例见 [`references/step5-ppt-cross-class-check.md`](references/step5-ppt-cross-class-check.md)。

### Step 6：提炼知识点（含证据分级与去重/矛盾检测）

**写入去向**
- 课程截图知识点 → `2_学习板块/2_知识点/2_待掌握/抖音AI夜校课程知识点.md`
- 抖音碎片知识点 → `2_学习板块/2_知识点/2_待掌握/抖音知识碎片.md`
- 实战过程中夹带的知识点 → 也挑出来写入课程知识点文件

**证据分级（每条必标可信度）**
- 🟢 High：飞书官方课程截图、课件 PDF 等一手权威来源。
- 🟡 Medium：抖音知识碎片、实战过程截图（二手/经验性）。
- 🔴 Low：AI 推断内容（必须前缀「推断：」且标 🔴）。

**溯源与事实/判断分开**
- 每条用 `> 原始素材：![说明](相对路径)` 标来源（**事实标来源**）。
- 属于推断的，前缀「推断：」并标 🔴 Low。

**去重 / 矛盾检测（写入前必做）**
- 与 `2_待掌握/` 已有条目比对：相似度 > 70% 或同一原始素材图 → **不重复写入**；若来源不同，合并为一条并标 `🔀 已与 #N 合并（相似度 XX%）`，保留全部来源。
- 同一主题观点相反 → 标注 `⚡ 观点对立` 并列保留，不强制合并。
- 无法归类或存疑的条目放入「📥 收件筐」小节并说明原因。
- 不擅自打 `✅已掌握 / ⏳待掌握` 标记，保持"待分类/待掌握"状态。

### Step 7：原数据清理确认（防误删暂存目录）

只问"清不清暂存目录里的源文件"，默认保留未落实文件，已落实文件移回收站。完整安全闸门见 [`references/step7-source-cleanup.md`](references/step7-source-cleanup.md)。

### Step 8：更新索引与 README

- 更新 `素材/学习/抖音AI夜校/README.md` 的统计与链接。
- 更新 `资源/学习/README.md` 的课程索引。
- 更新 `2_学习板块/3_学习项目/抖音AI夜校/README.md` 的课表/导航。
- 确保所有目录链接指向 `README.md`，图片链接使用 markdown 语法。

### Step 9：汇总报告

结论先行，并给出下一步与是否需确认：

```
【结论】已归档 X 张素材、Y 份资源；提炼 N 条知识点（去重 M 条、合并 K 条、观点对立 P 对）。
【明细】课程截图 a 张、知识碎片 b 张、实战过程 c 张；课件 d 份、资料/链接 e 份。
【证据分布】🟢 High p 条 / 🟡 Medium q 条 / 🔴 Low r 条（含推断）。
【下一步】待你审阅 `2_待掌握/` 知识点后，可标记已掌握/待掌握。
【需确认】若涉及移动/删除，见上方清单，确认后再执行。
【清理】见 Step 7 原数据清理确认——若你确认清理，已落实源文件移入回收站，未落实保留。
```

## Eval 驱动与测试样例

本 Skill 的迭代不靠「感觉更好」，而靠可重复验证。分类脚本内置固定测试用例：

```bash
python scripts/classify_raw_materials.py --test
```

完整用例表见 [`references/eval-cases.md`](references/eval-cases.md)。

## 命名规范

- 课程目录：`YY.MM.DD 第X节 主题`（小写 `skill`，中文冒号）
  - 例：`26.8.10 第四节 skill实战：先找到好用的，再做出自己的`
- 时间线目录：`26.8.10skill实战：先找到好用的，再做出自己的`
- 板块分层：`素材/学习/...`、`资源/学习/...`（可扩展 `1_小说板块`、`3_个人板块`）
- **截图文件（收到截图后统一改名）**：`YY.M.DD_中文内容总结.扩展名`
  - `YY.M.DD` = 所属课程日期（按**内容语义**判定课程，非文件名拍摄时间）；`中文内容总结` = 2–12 汉字概括核心内容。
  - **改名前必须先询问用户是否改名，并提供「自定义改名」选项**；用户拒绝则保留原文件名。
  - **改名后必须回填 wikilink（防死链）**。

完整规范与脚本状态见 [`references/naming-convention.md`](references/naming-convention.md)。

## 知识库管线（同步职责边界）

> 本 Skill **不负责同步**。飞书分享/备份同步由 `Zero-WYM-sync-skill` **独占负责**（其 SKILL.md 为唯一权威源，含脚本清单 / 平台限制 / 路径陷阱 / 自动化）。用户说「同步到飞书」「跑一下同步」「大 PPT 怎么传飞书」等，应加载 `Zero-WYM-sync-skill`，而非本 Skill。

## 与其他文件的关系

- 本 Skill 仅负责**本地归档流程**（素材/资源分类 + 知识点提炼），**不负责**飞书分享/备份同步；这些由 `Zero-WYM-sync-skill` 独占负责。
- `Zero-WYM-brain-skill`（操作手册）Skill 是用户与 AI 对话时的行为约束，本 Skill 的 6 要素 / 5 维 / 复杂度闸门 / Eval 即源于此；同步能力也已回填进其「技能调度表」与「进化案例」。
- `AI协作提示词_素材与资源.md` 为早期废弃版本，已迁入 `第二大脑/_归档/旧提示词/`，**请勿引用**。
- `screenshot-knowledge-extractor` 与 `obsidian-rename-sync` 已并入本 Skill（截图提炼的「实战项目记录」结构与改名后的 wikilink 回填能力），不再作为独立 skill 存在。
- 配合方式：先用本 Skill 整理，再加载对话规则提示词做后续知识加工。
